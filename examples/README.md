# RepoPilot end-to-end fix demo / RepoPilot 端到端修复演示

## English

### What the demo shows

This demo runs RepoPilot against a self-contained calculator repository with one real logic bug:
`divide(6, 3)` returns `-2.0` instead of `2.0`. The fixture starts with three passing tests and one
failing test. A successful fix run shows the complete path:

`plan → propose_patch → human approval → apply_patch → run_tests → git_commit → DONE`

`git_create_branch`, `apply_patch`, `run_tests`, and `git_commit` are high-risk actions. RepoPilot
stops at the approval gate for each one; approve only after reviewing the displayed action and, for
`apply_patch`, the complete diff.

The reproducible source and scripts live in `examples/`. The two GIFs are owner-recorded artifacts
from real-key runs and should be written to:

- `docs/assets/demo-cli.gif`
- `docs/assets/demo-console.gif`

### Prerequisites and recording safety

Put a real provider key in `.env`, then install the development environment:

```console
uv sync --dev
```

The repository's packaged runtime image is the alternative for the Compose path below.

Keep the key only in `.env`. Never type it into a command, render `.env` with `cat`,
`Get-Content`, or an editor while recording, or include it in `examples/demo.tape`. The commands in
this runbook do not print the key.

### CLI path: the reproducible core

Run these commands from the RepoPilot repository root:

```console
python examples/prepare_demo.py --dest data/demo-workspace
uv run repopilot run --task-type fix --repo data/demo-workspace "divide() returns the wrong sign; fix it so the tests pass"
```

`prepare_demo.py` safely recreates a workspace previously generated by this script, copies the
fixture without Python caches, initializes a new Git repository, configures a local demo identity,
creates a baseline commit, and prints the clean workspace path. It refuses to overwrite an unrelated
existing directory and never initializes Git inside `examples/demo-repo/`.

The expected live sequence is a plan, a proposed one-line diff, and four approval prompts. Enter
`y` at the `git_create_branch`, `apply_patch`, `run_tests`, and `git_commit` prompts after checking
each request. The tests should turn green, `git_commit` should create the terminal work-branch
commit, and the final result should be `DONE`. The current CLI renders this as `status=DONE` in its
last summary line.

#### Record the CLI GIF

[VHS](https://github.com/charmbracelet/vhs) can replay the supplied tape:

```console
vhs examples/demo.tape
```

The tape fixes the terminal dimensions, types the commands, waits for the four expected approval
prompts, answers `y`, and writes `docs/assets/demo-cli.gif`. It records a real model run, so provider
latency or a model choosing an extra tool call can still require adjusting a wait or recording
interactively. Asciinema is a suitable alternative.

### Streamlit console path: the visual run

Recreate the workspace immediately before this run so the seeded bug is present again:

```console
python examples/prepare_demo.py --dest data/demo-workspace
```

The least-friction setup uses two host processes under the same host user. Start the API in one
terminal:

```console
uv run uvicorn app.api.app:create_app --factory --host 127.0.0.1 --port 8000
```

Start the console in a second terminal:

```console
uv run streamlit run app/console/app.py --server.port 8501
```

Open `http://localhost:8501`. Create a `fix` run, use `data/demo-workspace` as the repository, and
enter the same divide-sign task. Capture the live event stream, each approval card, the complete
`apply_patch` diff, the green test result, the terminal report, and the completed run in the
archive. Approve each high-risk action only after reviewing it. Save the browser recording as
`docs/assets/demo-console.gif`.

For the container path, build and start the current image, then initialize the workspace inside the
API container:

```console
docker compose up --build -d
docker compose exec api python examples/prepare_demo.py --dest /app/data/demo-workspace
```

Open `http://localhost:8501` and enter `/app/data/demo-workspace` in the repository field. Creating
the Git repository inside the container keeps its ownership aligned with the API process. A
host-initialized repository can trigger Git's `dubious ownership` protection inside the container;
this demo deliberately does not change `safe.directory` or application Git behavior.

### Repeat

Run `prepare_demo.py` again before every take. It replaces only a destination previously generated
and marked by this script with a fresh copy, refuses to overwrite unrelated directories, and leaves
`examples/demo-repo/` unchanged.

## 中文

### 演示内容

这个演示让 RepoPilot 在一个自包含的小计算器仓库上修复一个真实逻辑 bug：
`divide(6, 3)` 错误地返回 `-2.0`，正确结果应为 `2.0`。种子仓库初始状态是三个测试通过、
一个测试失败。完整修复链路是：

`plan → propose_patch → 人工审批 → apply_patch → run_tests → git_commit → DONE`

`git_create_branch`、`apply_patch`、`run_tests` 和 `git_commit` 都是高风险动作。RepoPilot
会在每一步停在审批门前；应先核对动作内容，并在 `apply_patch` 阶段读完完整 diff，再决定批准。

可复现源码与脚本位于 `examples/`。两个 GIF 必须由 owner 使用真实 key 实跑并录制，落点是：

- `docs/assets/demo-cli.gif`
- `docs/assets/demo-console.gif`

### 前置条件与录屏安全

在 `.env` 中填入真实 provider key，然后安装开发环境：

```console
uv sync --dev
```

下文 Compose 路径也可使用本仓库构建的运行时镜像。

key 只放在 `.env` 中。录屏时绝不要把 key 写进命令，不要用 `cat`、`Get-Content` 或编辑器
展示 `.env`，也不要把 key 写进 `examples/demo.tape`。本 runbook 中的命令本身不会打印 key。

### CLI 路径：可复现主体

在 RepoPilot 仓库根目录运行：

```console
python examples/prepare_demo.py --dest data/demo-workspace
uv run repopilot run --task-type fix --repo data/demo-workspace "divide() 结果符号反了,修到测试通过"
```

`prepare_demo.py` 会安全重建此前由本脚本生成的目标目录、忽略 Python 缓存地复制种子仓库、
初始化新的 Git 仓库、配置仓库级演示身份、创建 baseline commit，并打印干净工作区路径。
它会拒绝覆盖无生成标记的普通目录，也绝不会在 `examples/demo-repo/` 中就地执行 `git init`。

预期真实链路会先给出计划和一行修复 diff，然后出现四次审批提示。核对请求后，依次在
`git_create_branch`、`apply_patch`、`run_tests`、`git_commit` 提示处输入 `y`。随后测试应全绿，
`git_commit` 应在工作分支创建终局提交，最终结果为 `DONE`。当前 CLI 最后一行摘要的实际显示是
`status=DONE`。

#### 录制 CLI GIF

可用 [VHS](https://github.com/charmbracelet/vhs) 回放随附 tape：

```console
vhs examples/demo.tape
```

tape 固定终端尺寸、敲入命令、等待四个预期审批提示、输入 `y`，并输出
`docs/assets/demo-cli.gif`。它录制的仍是真实模型调用，因此 provider 延迟或模型临时选择额外
工具调用时，可能需要调整等待时间或改为交互录制；也可使用 Asciinema。

### Streamlit 控制台路径：视觉演示

录这一版前先重新生成工作区，恢复种子 bug：

```console
python examples/prepare_demo.py --dest data/demo-workspace
```

最省心的方式是让两个进程都由同一宿主用户启动。在第一个终端运行 API：

```console
uv run uvicorn app.api.app:create_app --factory --host 127.0.0.1 --port 8000
```

在第二个终端运行控制台：

```console
uv run streamlit run app/console/app.py --server.port 8501
```

打开 `http://localhost:8501`，新建 `fix` run，仓库路径填 `data/demo-workspace`，任务填同一条
除法符号修复说明。录下实时事件流、每张审批卡、`apply_patch` 的完整 diff、全绿测试结果、
终态报告，以及归档中已完成的 run。每个高风险动作都应先核对再批准。浏览器录屏保存为
`docs/assets/demo-console.gif`。

容器路径则先构建并启动当前镜像，再在 API 容器内部初始化工作区：

```console
docker compose up --build -d
docker compose exec api python examples/prepare_demo.py --dest /app/data/demo-workspace
```

打开 `http://localhost:8501`，UI 仓库路径填 `/app/data/demo-workspace`。在容器内创建 Git
仓库，可以让属主与 API 进程一致。若在宿主上初始化后再交给容器，Git 可能触发
`dubious ownership` 保护；本演示不修改 `safe.directory`，也不改应用 Git 工具行为。

### 重跑

每次录制前重新运行 `prepare_demo.py`。脚本只替换此前由自身生成并标记的可丢弃目标目录，
会拒绝覆盖无关目录，并始终保持 `examples/demo-repo/` 不变。
